# BaoStock 数据同步性能优化与业务重构报告

## 1. 背景与挑战
在初始版本中，全市场 5,465 只股票的 K 线与复权因子同步面临以下瓶颈：
*   **速度极慢**：采用线性同步逻辑，处理全市场数据需 1 小时以上。
*   **IO 密集**：每一只股票都会触发独立的数据库查询与写入，导致极高的数据库连接开销。
*   **逻辑漂移**：原增量逻辑仅对比自然日，未考虑交易日历与数据发布延迟，存在大量无效抓取。
*   **资源限制**：容器受限于 128MB 内存，并发控制不当极易触发 OOM。

## 2. 核心优化方案 (Performance Tech Stack)

### 2.1 批量元数据预取 (Metadata Batching)
*   **优化前**：在循环中为每只股票执行 `SELECT MAX(trade_date)`。
*   **优化后**：启动前执行一次全局聚合查询，将全市场最新的同步进度缓存至内存字典。
*   **效果**：扫描阶段耗时从分钟级降至 **100ms**。

### 2.2 进程级并行抓取 (Process-Level Parallelism)
*   **技术方案**：引入 `ProcessPoolExecutor`（限制为 2 个 Worker）。
*   **原因**：突破 BaoStock Python 驱动在单进程内的阻塞限制。
*   **配置**：结合 `asyncio.Semaphore(10)`，在等待网络返回时保持高吞吐，同时兼顾内存安全。

### 2.3 缓冲区批量写入 (Batch SQL Upsert)
*   **机制**：实现 `db_buffer` 缓冲机制，积攒 **500 行**数据执行一次 `execute_many`。
*   **SQL 策略**：使用 `ON DUPLICATE KEY UPDATE`，确保写入的幂等性（防重、防冲突）。
*   **性能**：数据库 IO 往返次数降低了 **99%**。

## 3. 专业级业务逻辑升级

### 3.1 交易日基准锚定 (Trading Day Awareness)
*   **智能决策**：引入 `trade_cal` 交易日历校验。系统自动识别“最近一个已闭市交易日”作为同步目标。
*   **发布感知**：在全量启动前，对权重股进行单日探测。若数据源尚未更新当日数据，任务自动挂起并等待，消除无效负载。

### 3.2 串行同步流水线 (Comprehensive Pipeline)
*   **设计模式**：将 K 线同步与复权因子同步整合为 `daily_comprehensive_sync_job`。
*   **执行策略**：采取 **“先价格、后因子”** 的串行模式。
*   **优势**：在 128MB 极其受限的内存环境下，确保系统资源始终聚焦于单一任务，极大提升了生产环境的稳健性。

## 5. 运维说明
*   **断点续传**：系统每处理 10 只股票会自动记录索引。若中途崩溃，重启后将自动从 `last_index` 恢复。
*   **立即触发**：可通过 POST `/api/v1/sync/full` 传入 `start_date` 手动触发大范围补录。
*   **自动调度**：每日 **18:30** 准时启动综合流水线。
