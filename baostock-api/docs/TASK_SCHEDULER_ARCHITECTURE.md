# 架构文档：股票数据系统集成任务管理与核验

## 1. 概述
本系统实现了一套跨微服务容器的定时任务管理与垂直数据核验体系。通过 BaoStock API 作为中心网关，实现了对 AkShare 和 PyWencai 容器任务状态的实时聚合与控制。

## 2. 核心架构：Aggregator 模式
系统采用“主从聚合”架构：
- **主节点 (baostock-api)**: 负责对外公开统一的任务管理 API，并自动探测内网环境中的其他服务容器。
- **业务节点 (akshare-api, pywencai-api)**: 部署标准的任务执行引擎 (APScheduler)，并通过统一的 REST Endpoints 响应状态查询和控制指令。

### 交互时序
1. 前端发送 `GET /scheduler/jobs` 请求至网关。
2. 网关并发请求 `http://akshare-api:8000/...` 和 `http://pywencai-api:8000/...`。
3. 网关将本地任务与远程响应合并，并按 UI 适配格式返回。

## 3. 数据同步质量校验 (Data Audit)
系统通过 `/api/v1/sync/verify/daily` 定点核验每日数据的一致性：
- **市场基准**: 实时调用 BaoStock 的 `query_all_stock` 获取活跃 A 股列表。
- **实际条数**: 统计 MySQL 中指定日期的 K 线记录总数。
- **健康指标**:
  - `Completeness (%) = (实际条数 / 市场基数) * 100`
  - 阈值：< 95% 标记为 `incomplete`，0 条标记为 `no_data_yet`。

## 4. 任务控制指令
所有任务均支持以下原子操作：
- `run`: 立即触发一次后台异步执行（不影响下一周期调度）。
- `pause`: 挂起后续调度。
- `resume`: 恢复正常调度。

## 5. 本地开发与运维
- **依赖库**: `apscheduler`, `httpx`。
- **配置**: 定时任务时间在各容器的 `lifespan` 或配置文件中统一定义。
- **观察**: 在 UI 实时日志中，系统会自动打印数据核验报告，例如：
  `[INFO] 数据核验完成：2025-12-26 入库 5465 条，全市场预期 5465 条，完整度 100.0%`
