# Epic 14: AI-Driven Policy Tracking System (MVP)

## 背景
建立一个基于 AI 的政策跟踪系统，解决投资者在处理海量宏观政策信息时的「预警、追踪、对比、映射、日历」五大核心痛点。

## 核心架构
系统分为采集、处理、分析、映射、辅助决策和交互六层，采用 Python + LLM (DeepSeek/Claude) + SQLite 的轻量级架构。

## 风险评估
| 风险 | 影响 | 可能性 | 应对措施 |
|---|---|---|---|
| 政府网站反爬 | 高 | 中 | 优先使用 RSS 订阅，控制采集频率（>5min），模拟真实浏览器请求。 |
| LLM 幻觉 | 中 | 高 | 摘要后保留原文链接，重要政策强制人工核对。 |
| 政策映射误导 | 高 | 中 | 映射结果标注「待观察」，严禁虚假因果联想。 |

## 实施里程碑
- **M1**: 核心数据采集与 AI 摘要流水线跑通 (Week 2)
- **M2**: 建立历史政策库与措辞变化检测功能 (Month 1)
- **M3**: 完整日报与预警系统交付 (Month 3)

## E14-S1: 数据采集层建设 (Data Acquisition)

### 角色: [scf-collector]
**我想** 实现对政府网、央行、证监会等权威源的自动化监控，**以便** 获得一手政策情报。

#### 任务
- `[ ]` E14-S1-T1: 实现中国政府网 (gov.cn/zhengce) 政策文件的抓取适配器。
- `[ ]` E14-S1-T2: 实现央行 (PBC) 与证监会 (CSRC) 公告栏目的定时扫描逻辑。
- `[ ]` E14-S1-T3: 建立基于 RSS 的降级监控机制，确保在主爬虫失效时仍有信号。

#### 验收标准 (AC)
- **AC1: 采集覆盖度验证**
  - **Given**: 系统运行在采集模式。
  - **When**: 访问上述 3 个核心机构页面。
  - **Then**: 能够准确解析出「标题、发布时间、发文机构、原文链接、正文内容」。
- **AC2: 频控与反爬防护**
  - **Given**: 多线程并发采集。
  - **When**: 触发预设的 300s 间隔。
  - **Then**: 无 403 封禁，请求成功率 > 99%。

## E14-S2: AI 分析层与措辞对比 (AI Intelligence)

### 角色: [AI Analyzer]
**我想** 利用 LLM 对政策进行三句话摘要和历史措辞对比，**以便** 快速提炼核心增量信息。

#### 任务
- `[ ]` E14-S2-T1: 设计 Prompt 1 (三句话摘要) 和 Prompt 2 (措辞变化检测) 并完成本地测试。
- `[ ]` E14-S2-T2: 集成 DeepSeek/Claude API，实现长文本自动摘要与结构化输出。

#### 验收标准 (AC)
- **AC1: 摘要质量验证**
  - **Given**: 某篇 2000 字以上的行业政策。
  - **When**: 运行摘要流水线。
  - **Then**: 输出严格符合「核心内容、关键变化、主要影响」三段式，每段 < 50 字。
- **AC2: 措辞敏感度测试**
  - **Given**: 两段相似但强度不同的官方表述（如「积极推进」 vs 「稳慎推进」）。
  - **When**: 运行对比 Prompt。
  - **Then**: JSON 返回值中 `intensity_change` 必须准确识别出「减弱」。

## E14-S3: 知识库与板块映射 (Mapping & Storage)

### 角色: [Data Architect]
**我想** 建立政策-申万板块映射关系及 SQLite 存储，**以便** 进行回测和持仓影响分析。

#### 任务
- `[ ]` E14-S3-T1: 初始化 SQLite 数据库，设计 `policies` 与 `policy_market_reactions` 表结构。
- `[ ]` E14-S3-T2: 建立基础的「政策关键词 - 申万板块 - 代表标的」映射表。

#### 验收标准 (AC)
- **AC1: 数据持久化验证**
  - **Given**: 采集到一条新政策并经过 AI 处理。
  - **When**: 执行入库操作。
  - **Then**: `policy.db` 中对应字段非空，且 `keywords` 存储为标准 JSON 格式。
- **AC2: 自动映射准确性**
  - **Given**: 政策包含关键词「科技金融」。
  - **When**: 运行映射逻辑。
  - **Then**: 关联板块必须包含「计算机」或「电子」，代表标的中包含「寒武纪」等预设值。

## E14-S4: 辅助决策与交互 (Reporting)

### 角色: [Investment Advisor]
**我想** 自动生成每日简报并对持仓影响评分，**以便** 辅助最终投资决策。

#### 任务
- `[ ]` E14-S4-T1: 开发基于模板的「每日政策简报」生成脚本 (Markdown/HTML)。
- `[ ]` E14-S4-T2: 实现基于政策强度和重要性的持仓影响打分逻辑 (+5 到 -5)。

#### 验收标准 (AC)
- **AC1: 简报完整性**
  - **Given**: 当日有 5 条以上新政策。
  - **When**: 运行日报生成任务。
  - **Then**: 产出的报告包含「重大预警、一般关注、未来窗口预测」三大部分。
- **AC2: 告警及时性**
  - **Given**: 发现 5 星级重要政策。
  - **When**: 采集完成后的 60s 内。
  - **Then**: 触发系统告警通知。
