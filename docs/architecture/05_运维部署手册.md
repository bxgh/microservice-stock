# 05. 运维部署手册 (Operations Manual)

> **目标**: 提供 Copy-Paste 级别的部署指令，确保环境一致性。

## 1. 端口与网络白名单 (Security Groups)

### 1.1 腾讯云防火墙配置 (Inbound)

| 端口 | 协议 | 来源限制 | 用途 |
|:---|:---|:---|:---|
| **80** | TCP | 0.0.0.0/0 | HTTP (Let's Encrypt 验证) |
| **443** | TCP | 0.0.0.0/0 | HTTPS (Web/API 访问) |
| **22** | TCP | 您的内网IP | SSH 管理 |
| **26300** | TCP | 您的内网IP | MySQL 云数据库直连 |
| **465** | TCP | 0.0.0.0/0 | SMTP (发邮件告警) |

> \*: 如果使用 Docker Network 内部调用，则无需开放 6379 公网访问。但 26300 (MySQL CDB) 必须对内网 IP 开放。若使用加密发信，需确保云服务器出站 465 端口开放。

## 2. Docker Compose 编排文件

### 2.1 云端 (`/opt/stock/docker-compose.cloud.yml`)

```yaml
version: '3.8'

services:
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/conf.d:/etc/nginx/conf.d:ro
      - ./nginx/certs:/etc/nginx/certs:ro
      - ./dist:/usr/share/nginx/html:ro
    depends_on:
      - cloud-api

  cloud-api:
    build: ./cloud-api
    environment:
      - DB_HOST=sh-cdb-h7flpxu4.sql.tencentcdb.com
      - REDIS_HOST=redis
    deploy:
      resources:
        limits:
          memory: 800M

  redis:
    image: redis:7-alpine
    command: redis-server --requirepass ${REDIS_PASSWORD}
    volumes:
      - redis_data:/data
    deploy:
      resources:
        limits:
          memory: 1.5G

  # 数据采集器 (Limit 256M)
  akshare-api:
    build: ./akshare-api
    deploy: { resources: { limits: { memory: 256M }}}
  
  baostock-api:
    build: ./baostock-api
    deploy: { resources: { limits: { memory: 256M }}}

volumes:
  redis_data:
```

### 2.2 内网 (`/home/user/stock/docker-compose.home.yml`)

```yaml
version: '3.8'

services:
  clickhouse:
    image: clickhouse/clickhouse-server:23.8-alpine

      - CLOUD_DB_HOST=124.221.80.250
      - CH_HOST=clickhouse

      - ./logs:/app/logs
    depends_on:
      - clickhouse

  strategy-dispatcher:
    build: ./dispatcher
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock  # 允许操作 Docker
```

## 3. 环境变量配置 (.env)

项目根目录下的 `.env` 文件是系统运行的核心配置。

### 3.1 核心凭据
*   `TUSHARE_TOKEN`: 用于获取交易日历、复权因子等核心元数据。
*   `DB_PASSWORD`: 云 MySQL 访问密码。

### 3.2 邮件告警 (E6)
| 配置项 | 示例 | 说明 |
|:---|:---|:---|
| `SMTP_HOST` | `smtp.qq.com` | SMTP 服务器地址 |
| `SMTP_PORT` | `465` | SSL 端口 |
| `SMTP_USER` | `xxx@qq.com` | 发件人账号 |
| `SMTP_PASS` | `xxxx` | **授权码** (非登录密码) |
| `ALERT_RECEIVER` | `xxx@qq.com` | 接收告警的邮箱 |
| `ALERT_LEVEL_THRESHOLD` | `WARN` | 触发邮件的最低级别 |

## 4. 自动化监控与维护

### 4.1 数据就绪状态核验 (E2)
若怀疑数据缺失，可查询 `meta_data_readiness` 表：
```sql
-- 查看当日核心数据就绪情况
SELECT * FROM meta_data_readiness WHERE biz_date = CURRENT_DATE;
```

### 4.2 任务自愈逻辑
系统内置了“僵尸任务”清理器。若 `stock-manager` 日志中出现 `Cleanup zombie task: [ID]`，说明系统已自动将卡死超过 2 小时的任务标记为 `FAILED` 并释放资源。

## 5. 常见问题排查 (Troubleshooting)

### Q1: 内网连不上云端 MySQL (26300)
*   **检查**: `telnet 124.221.80.250 26300`
*   **原因**: 腾讯云 CDB 默认不开启外网访问。
*   **解决**: 登录腾讯云控制台 -> MySQL 实例 -> 开启外网地址 -> 设置白名单包含您的内网公网出口 IP。

### Q2: ClickHouse 启动报错 `Memory limit`
*   **检查**: `docker logs clickhouse`
*   **解决**: 修改 `users.xml` 配置，增加 `<max_memory_usage>10000000000</max_memory_usage>` (10GB)。

### Q3: 回测速度慢
*   **检查**: 是否没走 ClickHouse 而走了 MySQL？
*   **验证**: 查看 Worker 日志，确认 `Loading data from ClickHouse...` 字样。

### Q4: 任务在周末/节假日没有运行
*   **原因**: 系统集成了 `CalendarService` 交易日门禁。
*   **验证**: 查看 `stock-manager` 日志，若出现 `Skip task: non-trading day` 则为正常拦截，非系统故障。

### Q5: 修改了 .env 配置后不生效
*   **原因**: `docker restart` 不会重载环境变量。
*   **解决**: 必须运行 `docker compose up -d stock-manager` 触发容器重建以应用新配置。

# 常用运维别名 (Aliases)

建议添加到 `~/.bashrc`:

```bash
# 云端服务
alias logs-manager="docker logs -f stock-manager --tail=100"
alias check-ready="docker exec stock-manager python3 -c '...查询readiness脚本...'"

# 部署
alias deploy-all="docker compose up -d"
alias rebuild-manager="docker compose up -d --build stock-manager"
```
