# 混合云微服务融合架构规划

本规划旨在将原有的微服务架构（`akshare`/`baostock`/`pywencai`）有机融合到新的混合云（云端+内网）体系中，在保证功能完整性的同时，最大化利用内网算力，减轻云端资源压力。

## 1. 核心融合策略：动静分离与算力下沉

我们依据**已有的微服务代码资产**，按照"计算密集型下沉、IO密集/实时型上云"的原则进行重新编排。

| 微服务组件 | 原有定位 | 调整后部署位置 | 调整理由 |
|:---|:---|:---|:---|
| **akshare-api** | 实时/历史数据接口 | **云端** (保留) | 提供实时行情、财务数据，响应小程序即时请求，内存占用尚可。 |
| **pywencai-api** | 问财选股接口 | **云端** (保留) | 交互式选股需要即时响应，不适合经过内网穿透。 |
| **baostock-api** | 历史K线/数据同步 | **内网** (核心同步) + **云端** (只读副本) | **数据同步/清洗是重资源操作**，必须下沉到内网服务器执行；云端仅保留轻量级Read接口查库。 |
| **cloud-api** | (新增) 业务聚合 | **云端** | 作为新一代BFF (Backend for Frontend)，聚合上述基础数据服务。 |

## 3. 现有微服务的改造点

为了适应这种混合部署，现有的微服务代码需要做少量适配：

### 3.1 `baostock-api` (云端全量部署)
*   **变更背景**: 经确认，内网服务器无法访问外部数据源(BaoStock TCP/Web)，因此无法承担数据采集任务。
*   **部署策略**: 
    *   **完整部署于云端**: 负责历史K线查询(Read) + 每日定时同步(Write)。
    *   **资源限制**: 必须严格限制并发同步数量，避免耗尽云服务器 4G 内存。
    *   **内网交互**: 内网服务器不运行此服务，而是通过 API 调用云端接口获取清洗后的数据。

### 3.2 `akshare-api` & `pywencai-api` (云端部署)
*   **部署策略**: 维持云端部署，作为数据采集前哨。
*   **优化**:
    *   在 `docker-compose.yml` 中严格限制 `mem_limit: 256m`。
    *   配置 `gunicorn`/`uvicorn` 的 workers 数量为 1-2 个（云端并发量主要由IO决定，无需过多进程）。

## 4. 全局端口规划 (Port Mapping)

为了避免混乱，我们对云端和内网的端口进行统一规划。

| 服务 | 容器端口 | 云端宿主机端口 | 内网宿主机端口 | 说明 |
|:---|:---|:---|:---|:---|
| Nginx | 80/443 | 80/443 | - | 公网唯一入口 |
| Cloud-API | 8000 | 8000 (仅localhost) | - | 核心业务聚合 |
| AkShare | 8000 | 8003 (仅localhost) | - | 基础数据源1 |
| PyWencai | 8000 | 8002 (仅localhost) | - | 基础数据源2 |
| BaoStock | 8000 | 8001 (仅localhost) | - | 基础数据源3 |
| Redis | 6379 | 6379 (带密码/Tunnel) | - | 消息/缓存 |
| **Strategy Worker** | - | - | - | **内网主动连接云端，无监听端口** |

*   **安全注记**: 云端所有微服务端口(8000-8003)均不对外，仅通过 Docker Network 供 `Cloud-API` 调用，或 Nginx 转发。内网通过 HTTP/WS 协议访问 Nginx。

## 5. 实施步骤 (结合现有代码库)

### Phase 1: 容器编排调整 (Docker Compose)
您现有的 `docker-compose.yml` 比较简单。我们需要将其拆分为两份：
1.  `docker-compose.cloud.yml`: 包含 Nginx, Cloud-API, AkShare, PyWencai, Redis。
2.  `docker-compose.home.yml`: 包含 BaoStock (Sync Mode), Strategy Workers。

### Phase 2: 代码逻辑适配
1.  修改 `baostock-api/app/main.py`: 增加环境变量判断，如果非同步节点，不启动定时任务。
2.  开发 `cloud-api`: 这是一个新的 FastAPI 项目，用于替代直接暴露微服务，并处理鉴权。

### Phase 3: 数据库连接配置
*   云端服务直接连接 `localhost/internal-ip` 的 MySQL。
*   内网服务通过公网 IP (或 VPN) 连接云端 MySQL。

这一规划完美保留了您之前编写的微服务代码，只对其**运行时环境**和**职责**做了更合理的物理重新分配。
