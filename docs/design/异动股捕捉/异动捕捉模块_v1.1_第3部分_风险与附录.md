## 风险

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| MySQL 5.7 无窗口函数,排名计算复杂易错 | 🔴 高 | 关键排名计算用 Python pandas |
| 形态判定 22 个标签,Python 计算慢 | 🟡 中 | 派生指标层提前计算共用部分,标签判定只做轻量逻辑 |
| 标签互斥规则维护成本 | 🟡 中 | `dim_tag_relation` 表集中管理,代码侧用通用裁决函数 |
| 共振维度的标签归属定义需要持续调整 | 🟡 中 | `RESONANCE_DIMENSIONS` 配置化(可放配置表) |
| 反向信号数据源依赖 L6,需确认接口稳定 | 🟢 低 | L6 已生产,接口稳定 |
| 初始权重为经验值,前 1 个月推送质量不稳定 | 🟡 中 | 1 个月后用命中率反推调整 |
| `signal_features` JSON 结构演进 | 🟢 低 | `schema_version` 字段保兜底 |
| Profile 切换可能产生用户困惑 | 🟢 低 | 默认使用 `profile_default`,其他 Profile 留作进阶用户 |
| 中文解释生成可能出现语义不通的拼接 | 🟡 中 | 上线后人工抽检 100 条,迭代模板 |

```sql
CREATE TABLE `log_signal_lifecycle` (
  `id`               BIGINT UNSIGNED  AUTO_INCREMENT,
  `original_id`      BIGINT UNSIGNED  NOT NULL                 COMMENT '关联 ads_l8_unified_signal.id',
  `tracked_date`     DATE             NOT NULL                 COMMENT '追踪日期',
  `state`            VARCHAR(20)      NOT NULL                 COMMENT 'active/continuing/breaking/reversed/confirmed/failed/archived',
  `state_features`   JSON                                       COMMENT '当日状态特征',
  `delta_metrics`    JSON                                       COMMENT '相对触发日的变化指标',
  `extra`            JSON,
  `schema_version`   VARCHAR(10)      DEFAULT 'v1.0',
  `created_at`       TIMESTAMP        DEFAULT CURRENT_TIMESTAMP,

  PRIMARY KEY (`id`),
  KEY `idx_original` (`original_id`, `tracked_date`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
  ROW_FORMAT=DYNAMIC
  COMMENT='信号生命周期(阶段 2 启用)';
```

**用途规划**(阶段 2):

```yaml
信号生命周期追踪:
  T:   首次触发(进入异动池)
  T+1: 状态:延续 / 中断 / 反转
  T+5: 状态:确认 / 失败
  T+10: 状态:已验证(退出活跃池)
  T+20: 状态:进入历史档案

价值:不仅记录"今天 A 异动触发了",还记录"3 天前 B 异动现在状态如何"
     这是真正连贯的认知训练数据,与观察点系统的验证规则深度耦合
```
