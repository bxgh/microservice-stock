# E8 系统运维

部署、调度、监控、日志,**保证系统能持续稳定运行**。预计耗时 1 周。

## E8-S1 部署架构

**作为** 系统使用者,**我希望** 腾讯云 + 内网双节点架构清晰,**以便** 一台挂了不影响关键流程。

### 任务

- E8-S1-T1 腾讯云服务器作为生产环境(数据采集、AI 抽取、调度)
- E8-S1-T2 内网服务器作为开发/灾备环境(同步 MySQL slave、备份数据)
- E8-S1-T3 数据备份策略(每日 MySQL 备份至内网,每周 ClickHouse 备份)
- E8-S1-T4 部署文档 + Docker Compose 编排

### 部署架构

```
┌─────────────────────────────────────┐
│  腾讯云服务器 (生产)                │
│  ┌─────────────────────────────┐   │
│  │ Python 3.11                 │   │
│  │ MySQL 5.7 (Master)          │   │
│  │ ClickHouse                  │   │
│  │ Redis (任务队列)            │   │
│  │ APScheduler / crontab        │   │
│  └─────────────────────────────┘   │
└──────────────┬──────────────────────┘
               │ 数据同步 + 备份
               ▼
┌─────────────────────────────────────┐
│  内网服务器 (开发/灾备)              │
│  - MySQL Slave                      │
│  - ClickHouse 备份                  │
│  - 开发环境                         │
└─────────────────────────────────────┘
```

### 验收标准

- **AC1**: Docker 化部署
  - **Given** 一台干净的 Ubuntu 22.04 服务器
  - **When** 执行 `docker compose up -d`
  - **Then** MySQL、ClickHouse、Redis、Python 应用全部启动,可通过 `docker ps` 看到 4 个容器 running

- **AC2**: 数据备份
  - **Given** 系统运行 1 周
  - **When** 检查内网备份目录
  - **Then** `/backup/mysql/` 至少有 7 份每日备份,`/backup/clickhouse/` 至少有 1 份周备份

## E8-S2 调度系统

**作为** 系统使用者,**我希望** 所有定时任务集中管理,**以便** 我能清晰看到每个任务的状态。

### 任务

- E8-S2-T1 选型:crontab(简单)vs APScheduler(可观测性好)→ **方案对比见下**
- E8-S2-T2 实现核心调度任务(每日同步、每周扫描、每日报告)

### 方案对比

| 维度 | 方案 A:crontab | 方案 B:APScheduler |
|---|---|---|
| 部署复杂度 | 低(系统自带) | 中(需 Python 进程常驻) |
| 任务可观测性 | 低(需自己写日志) | 高(原生支持任务状态、失败重试) |
| 任务依赖管理 | 不支持 | 支持 |
| 学习成本 | 几乎为零 | 中等 |
| 适合场景 | 简单独立任务 | 任务有依赖、需要监控 |

### 选型结论

**第一阶段选 crontab**。原因:任务量少(每日 3-5 个、每周 1-2 个),无复杂依赖,crontab 足够。**未来若任务超过 20 个或出现复杂依赖,迁移到 APScheduler 或 Airflow**。

### 验收标准

- **AC1**: 任务调度生效
  - **Given** crontab 配置已部署
  - **When** 系统时间到达调度时刻
  - **Then** 任务在预定时间触发,执行日志写入 `/var/log/astock/`,包含开始时间、结束时间、退出码

## E8-S3 监控告警与日志

**作为** 系统使用者,**我希望** 系统异常被及时告警,**以便** 我不会因为系统挂了一周才发现。

### 任务

- E8-S3-T1 关键任务执行状态监控(成功/失败/超时)
- E8-S3-T2 数据库连接健康检查
- E8-S3-T3 AI API 调用失败率监控
- E8-S3-T4 告警通过邮件 + Bark 推送(手机端)
- E8-S3-T5 日志统一格式(JSON 格式,字段:timestamp, level, module, message, ts_code)

### 验收标准

- **AC1**: 任务失败告警
  - **Given** 某关键任务(如每日同步)执行失败
  - **When** 任务退出码非 0
  - **Then** 30 分钟内收到告警邮件,内容包含任务名、失败时间、错误日志摘要

- **AC2**: AI API 异常
  - **Given** 连续 5 次 AI 调用失败(网络问题或限频)
  - **When**监控脚本检测到
  - **Then** 推送告警,系统自动暂停 AI 抽取队列 30 分钟后重试
