# 技术报告 - E200-S1: 差异化跨源扫描器异常判定机制

## 1. 核心目标
差异化跨源扫描器（Scanner）旨在通过引入多方独立数据源，解决单数据源（Tushare/ODS）可能存在的脏数据、滞后或字段偏差问题。其核心逻辑在于构建一个具备“容错”与“仲裁”能力的自动化校验引擎。

## 2. 异常判定规则体系

本系统采用“三源仲裁，取二一致”的核心算法，将判定逻辑划分为以下五个核心维度：

### 2.1 容差基准 (Tolerance Standard)
为避免由于浮点数精度或四舍五入产生的误报，系统定义了严格的字段级容差：
- **价格类 (OHLC)**: `0.01%` (0.0001)。任何源之间的相对差异小于此值视为一致。
- **体量类 (Volume/Amount)**: `0.1%` (0.001)。

### 2.2 逻辑仲裁矩阵 (Arbitration Matrix)

系统基于三方数据源（**A**: 本地 ODS, **B**: Mootdx, **C**: AkShare）的匹配结果，执行以下逻辑判定：

| 匹配模式 | 判定结果 | 严重程度 | 处理动作 |
| :--- | :--- | :--- | :--- |
| **A == B == C** | 数据准确 | `INFO` | 不记录，继续流程 |
| **A == B != C** | AkShare 异常 | `WARN` | 记录日志，标识 C 源质量问题 |
| **A == C != B** | Mootdx 异常 | `WARN` | 记录日志，标识 B 源质量问题 |
| **B == C != A** | **ODS 数据错误** | `ERROR` | **触发报警**，建议执行 ODS 补数修复 |
| **A != B != C** | 深度不一致 | `ERROR` | **触发报警**，标记为“需人工介入” |

### 2.3 数据源降级逻辑 (Degradation)
当外部源（B 或 C）因网络波动、限流、超时或 404 返回 `None` 时，系统自动触发降级逻辑：
- **单源失效**: 退化为“双源比对”。若存余两源不一致，判定为 `WARN`（由于无法仲裁，仅做预警）。
- **双源失效**: 停止跨源扫描，仅依赖本地校验逻辑（Stage E 原有逻辑）。

## 3. 字段适配与标准化 (Standardization)
由于不同数据源对“成交量”的定义不同，Scanner 在比对前执行了强制标准化：
- **Tushare (ODS)**: 存储单位为“股”。
- **Mootdx**: 接口返回单位为“手”，Scanner 自动执行 `vol * 100` 换算。
- **AkShare**: 接口已标准化为“股”。

## 4. 存证与闭环
异常判定结果实时写入 `dq_findings` 表。该表包含 `diff_data` JSON 字段，完整记录了三方源的原始镜像及差异路径。
- **Rule ID**: `CROSS_SOURCE`
- **Severity**: `WARN` / `ERROR`
- **Status**: `OPEN` (待 E200-S2 Healer 组件处理)
