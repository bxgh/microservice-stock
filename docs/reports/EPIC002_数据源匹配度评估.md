# EPIC-002 数据源匹配度深度评估报告

本报告旨在评估当前微服务集群（8000-8003）提供的数据能力与 `EPIC-002 数据集成需求` 的匹配程度，并识别潜在的技术缺口。

---

## 1. 总体匹配度概览

| 需求模块 | 匹配度 | 评估结论 |
| :--- | :--- | :--- |
| **需求 1: 财务指标集成** | 85% | 底层库（AkShare）包含 95% 原始字段，但 API 层目前仅暴露了核心摘要。 |
| **需求 2: 历史财务数据** | 90% | AkShare 报表接口支持历史查询，需在上层逻辑中实现多周期拼接。 |
| **需求 3: 市场估值数据** | 70% | 核心 PE/PB 已支持，但股息率、市现率等字段需从最新快照中扩容提取。 |
| **需求 4: 估值历史数据** | 60% | 原始数据（5年历程）充足，但**分位值统计逻辑（Mean/P90等）**存在缺口。 |
| **需求 5: 行业统计数据** | **20%** | **关键缺口**: 底层库不直接提供行业分位统计，需进行全样本聚合计算。 |
| **需求 6: 基本信息增强** | 100% | 8001/8003 接口可完美覆盖申万行业分类与上市日期。 |

---

## 2. 深度技术穿透分析

### 2.1 财务指标 (Requirement 1 & 2)
*   **已支持 (Direct)**: 营业收入、净利润、总资产、净资产、经营现金流、ROE。
*   **底层具备但需 API 扩容 (Needs Mapping)**: 货币资金、应收账款、存货、总负债、商誉、有息负债相关细项（短期借款等）。
*   **计算型字段 (Logic Gap)**: 
    *   **EBIT/EBITDA**: 需要从利润表中通过公式计算。
    *   **自由现金流 (FCF)**: 需从现金流量表中计算 `经营现金流 - 资本性开支`。

### 2.2 估值指标 (Requirement 3 & 4)
*   **已支持**: 总市值、PE-TTM、PB。
*   **API 层缺口**: 
    *   **市销率 (PS) & 市现率 (PCF)**: 8003 端口的 `stock_zh_a_spot_em` 包含这些数值，但当前的 `get_valuation_spot` 尚未提取。
    *   **股息率**: 需从行情快照中同步提取。
*   **统计缺口**: 需求要求返回历史 PE 均值、中位数及各分位点。这需要微服务在获取 5 年历史数据后，在内存中进行 `numpy` 或 `pandas` 统计运算。

### 2.3 行业深度聚合 (Requirement 5) - **最大挑战**
*   **现状**: 外部数据源（AkShare/BaoStock）通常只提供“个股所属行业”，或“行业内成分股列表”，**不直接提供**类似“农林牧渔行业 ROE 中位数”的聚合统计。
*   **实现路径建议**: 
    1.  调用 8000/8001 获取特定行业的股票清单（约 30-200 只）。
    2.  并行调用 8003 获取这些股票的最新财务/估值指标。
    3.  在 Service 层进行 `group by` 和分位数计算。

---

## 3. 落地建议与改进方案

### 方案 A：微服务层扩展 (推荐)
- **8003 (AkShare)**: 升级 `get_valuation_spot` 方法，将 `ak.stock_zh_a_spot_em` 中剩余的 10+ 个估值字段全量输出。
- **8001 (BaoStock)**: 在 `get_valuation_history` 中集成统计函数，当请求参数包含 `stats=true` 时，自动计算并返回 Mean/Median/P90 等指标。

### 方案 B：上层中台计算
- 在 `get-stockdata` 服务的 `logic/calculator.py` 中，针对 EBIT、EBITDA、FCF 等非标财务指标，根据 8003 提供的原始三大报表进行后验计算。

---

## 4. 结论
当前数据源**完全满足** P0 级的数据“厚度”，但在“逻辑层”和“统计聚合”方面仍有约 30% 的工作量需要在 Service 层或集成层完成。特别是**需求 5（行业统计）**，如果实时性要求极高，建议建立独立的“行业快照缓存表”。
