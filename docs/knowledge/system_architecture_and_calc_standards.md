# 知识库：微服务架构设计与指标计算标准

## 1. 指标分层架构 (Indicator Taxonomy)
系统按照“复盘体系”深度，将指标划分为五个逻辑层级，开发时应严格遵循层级依赖：
*   **L1 (Panorama/全景)**：市场整体基调。包括涨跌家数、全市场广度、新高新低（60d/250d）。
*   **L2 (Structure/结构)**：主线交易归因。包含申万行业分化、风格因子强弱、概念板块动量。
*   **L3 (Sentiment/情绪)**：短线情绪周期。涵盖连板高度、涨跌停统计、炸板率、昨日涨停表现。
*   **L4 (Capital/资金)**：大体量资金流向。包括北向资金、融资融券、主力/大单流向。
*   **L5 (Focus/焦点)**：个股异动。包含龙虎榜分析、异动池标签、研报关键锚点提取。

---

## 2. 数据单位与精度规范
为避免跨服务调用时的量纲冲突，统一执行以下标准：
*   **金额 (Currency)**：所有涉及“成交额”、“市值”的字段，入库单位统一为 **元 (Yuan)**。
    *   *注意*：Tushare 返回的 `amount` 通常为千元，入库前必须乘以 1000。
*   **涨跌幅 (Percentage)**：统一使用 **小数 (Decimal)** 表示。
    *   *示例*：`0.0521` 代表 `5.21%`。
*   **日期 (Date)**：接口传递统一使用 `YYYY-MM-DD` 字符串，内部逻辑使用标准 `date` 对象。

---

## 3. 服务协作与降级策略
*   **中控逻辑**：`stock-manager-api` 负责调度与指标聚合，不直接连接外部 API。
*   **数据源分工**：
    *   **BaoStock (Primary)**：负责日线 K 线主数据，需处理 Broken Pipe 自动重连。
    *   **Tushare (Secondary/Fallback)**：负责因子表、指数日线及节假日数据补全。
    *   **AkShare (Event/Realtime)**：负责涨跌停池、概念板块行情、实时盘中数据。
*   **微服务寻址**：使用 Docker 内部容器名（如 `http://akshare-api:8000`），严禁硬编码外部 IP。

---

## 4. 性能红线与计算模式
由于系统运行在资源受限环境（128MB 内存），计算任务必须遵守：
*   **内存约束**：单个任务堆栈占用必须 **≤128MB**。
*   **计算模式 (Memory-First)**：
    *   严禁在 MySQL 5.7 中执行跨度超过 20 天的大表相关子查询。
    *   推荐采用 **“全量拉取 + Python 分组迭代”**。即：拉取所需窗口的所有数据到内存，使用 `itertools.groupby` 配合 `bisect` 算法完成逻辑比对，最后使用 `execute_many` 批量入库。

---

## 5. 质量控制 SOP (QC Standard)
每次代码变更后必须执行：
1.  **Health Check**：访问 `/health` 确认 `details.memory_usage` 为 `normal`。
2.  **Logic Regression**：对于重算的指标，必须比对修正前后的 `high_60d` 等关键数值，确保趋势逻辑闭环。
3.  **Documentation Sync**：架构或 API 变更必须同步更新 `docs/` 和相关知识库。
