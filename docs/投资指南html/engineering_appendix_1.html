第一区 · 市场状态总览

Zone 1 · Market State Overview
1.1

当前主导资金识别

dominant_capital_identification()
MEDIUM
核心思路
计算每一类资金的"活跃度评分",评分最高的就是当前主导资金。用Z-score标准化消除规模差异,加入持续性权重防止单日异动误判。
计算公式
ActivityScore_i = Z(NetFlow_i, 20d) × Continuity_i Z(NetFlow_i, 20d) = (今日净流入 − 20日均值) / 20日标准差 Continuity_i = 过去5日中同向流入的天数 / 5
输出规则
  • 取活跃度评分最高的资金类别作为"当前主导资金"
  • 当评分最高的两类资金分数差距 < 0.3σ 时,显示为"双主导"
  • 当所有资金活跃度都在 ±0.5σ 内时,显示为"过渡期"
实现要点
  • 各类资金的具体净流入计算见第二区温度计章节
  • 20日窗口平衡灵敏度与稳定性
  • 持续性权重防止偶发异动误判

state_switch_probability()
HARD
简单版 · 历史频率法
def simple_switch_prob(current_features): # 找出过去5年最相似的N=20个样本 similar = find_nearest_neighbors( current_features, history_data, n=20, metric='euclidean' ) # 统计这些样本5天内切换的比例 switch_count = sum( 1 for s in similar if s.switched_within_5d ) return switch_count / len(similar)

  • VIX(中国版波动率指数)的变化

第二区 · 九类资金温度计

Zone 2 · Capital Thermometers

每根温度计都是一类资金的标准化活跃度可视化。统一框架是Z-score标准化,但每一类资金的具体数据源和计算细节不同。下面是九类资金的完整实现规范。

NationalTeam_NetFlow = Σ(ETF_i份额变化 × ETF_i单位净值) Score = (今日NetFlow − 60日均值) / 60日标准差
数据源
  • akshare: fund_etf_fund_daily_em()

▸ 特殊提示
国家队特点是"低频但巨大"。日常多数时候温度计在中性区域。当出现 >2σ 的正向流入时,系统应弹出醒目提示——通常是关键信号。
2.2/2.3

温度计二三 · 北向配置盘 vs 交易盘

northbound_dual_pool_thermometer()
HARD
▸ 信息密度最高的指标
这两根温度计是状态屏中信息量最大的指标。两者的相对关系比绝对值更重要——它能识别出市场的"潜在底部"和"潜在顶部"。
配置类托管行白名单
  • HSBC Bank PLC
  • JP Morgan Chase Bank
  • Citibank N.A.
  • Standard Chartered Bank
  • Deutsche Bank AG
  • BNP Paribas Securities Services
交易类托管行白名单
  • Goldman Sachs International
  • Morgan Stanley & Co International
  • UBS AG
  • Barclays Capital Securities
计算公式
配置盘资金流 = Σ(配置类托管行_i 持股市值变化) 配置盘Score = (今日配置盘资金流 − 20日均值) / 20日标准差 交易盘资金流 = Σ(交易类托管行_i 持股市值变化) 交易盘Score = (今日交易盘资金流 − 20日均值) / 20日标准差 持股市值变化 = (今日持股数 − 昨日持股数) × 今日收盘价
两者背离的信号矩阵 · CRITICAL
配置盘 交易盘 市场含义
绿(+) 绿(+) 共识看多,趋势强化
绿(+) 红(−) 长线进场 vs 短线避险 — 潜在底部信号
红(−) 绿(+) 长线撤退 vs 短线博弈 — 潜在顶部信号
红(−) 红(−) 共识看空,系统性下跌
数据获取
  • HKEX官网爬虫: https://www.hkexnews.hk/sdw/
  • Wind: "陆股通持股明细"
  • Choice: "沪深港通持股"
  • 同花顺iFinD: 北向资金分托管行
⚠ DATA CLEANING
CCASS数据按"参与者+股票代码"明细发布,需要按托管行聚合并清洗(排除发起人持股、法人持股)。这部分工作量大,建议直接用商业数据源。
2.4

温度计四 · 公募基金

mutual_fund_thermometer()
MEDIUM
⚠ CHALLENGE
九类资金中最难精确测量的。公募实际持仓只在季报披露(滞后约15天),日度估算需要用间接指标。
三因子合成公式
公募活跃度 = 0.4 × 仓位变化Score + 0.3 × 新发申购Score + 0.3 × ETF场内份额Score
因子 计算方法 数据源 更新
仓位变化Score 基于卖方仓位测算,前5日仓位变化标准化 中信/兴业卖方研报 周
新发申购Score 中基协月度新发数据,日度线性插值 中基协 / Wind 月
ETF场内份额Score 所有股票型ETF场内份额日变化 akshare fund_etf_category_sina() 日
▸ 校准机制
每季度公募季报披露后,用真实数据校准日度估算的偏差。如果发现某个因子的预测力衰减,调整权重。

温度计五 · 量化基金

quant_fund_thermometer()
HARD

量化活跃度 = 0.30 × 指增超额Score + 0.25 × 小微盘强度Score + 0.25 × 期货贴水Score + 0.20 × 成交集中度Score
因子 计算方法 数据源
指增超额Score 中证500/1000指增滚动20日超额收益 好买基金 / 私募排排网

温度计六 · 险资

insurance_capital_thermometer()
MEDIUM
数据特点
高频数据极难获取,主要依赖月度披露 + 事件驱动更新。
合成逻辑
日常温度 = 月度险资增减仓 / 22交易日 事件驱动 = 险资举牌、大宗增减持(即时) 温度计显示 = 日常温度 + 事件驱动加权
数据源

  • 中保协人寿险投资数据
▸ 特殊提示
险资温度计大部分时间显示"近中性"(月度数据高度平滑)。但出现险资举牌时,温度计应立即跳到强正值并附弹出说明。

温度计七 · 游资

hot_money_thermometer()
HARD
底层数据
龙虎榜每日席位数据 + 自维护的游资席位库(50-100个核心席位)。
三因子合成公式
游资活跃度 = 0.4 × 上榜席位数Score + 0.3 × 净买入金额Score + 0.3 × 题材集中度Score
游资席位库维护
这是一个需要持续投入的"私有数据资产":
  • 初始化:从知名财经网站收集50-100个核心游资席位
  • 维护:每月review上榜频次,新增活跃席位,移除沉寂席位
  • 标签:每个席位标注偏好题材、操作风格、典型规模

03

第三区 · 六大警戒灯

Zone 3 · Six Warning Lights

警戒灯是状态屏中最具触发性的指标。每个灯都是一个二元判断:绿(正常)、黄(警觉)、红(危险)。任何一个灯变红,系统强制弹出说明窗口。

3.1

警戒灯一 · 流动性环境

liquidity_environment_light()
EASY
核心指标
DR007(银行间7天质押式回购利率) + 10年期国债收益率
数据源
  • DR007: 中国货币网
  • 10年期国债: 中国债券信息网
  • M1: 国家统计局 / 人民银行
  • 简化: Wind / Choice / Tushare
三色判定规则
绿灯
全部满足: DR007 < 2.5% · 10Y国债 < 2.8% · M1同比 > 0% · 央行净投放
黄灯
任一满足: 2.5% < DR007 < 2.8% · 10Y国债20日上行>30bp · M1同比转负
红灯
任一满足: DR007 > 2.8% · 10Y国债20日上行>50bp · 央行连续大额回笼
3.2

警戒灯二 · 公募仓位

mutual_fund_position_light()
EASY
核心指标
偏股混合型基金平均仓位
数据源
  • 中信/兴业/招商每周一卖方研报
  • Wind: "基金仓位测算"
  • 简化:追踪代表性基金净值反推
三色判定规则
绿灯
仓位 < 80%(还有加仓空间)
黄灯
80% ≤ 仓位 ≤ 88%(中性偏高)
红灯
仓位 > 88%(高位预警)
▸ 二级触发
当公募仓位连续3周下降时,即使绝对值还在黄灯区,也应该弹出"机构调仓中"提示。
3.3

警戒灯三 · 量化拥挤度

quant_crowding_light()
MEDIUM
三因子合成
拥挤度Score = 0.4 × 指增超额z + 0.3 × 小微盘强度z + 0.3 × 期货贴水z
分位数计算
每个因子用过去3年数据计算分位数,综合得分用同样窗口确定分位。
三色判定规则
绿灯
综合分位 < 60%(拥挤度低)
黄灯
60% ≤ 综合分位 ≤ 85%(中度拥挤)
红灯
综合分位 > 85%(流动性危机风险)
⚠ ESCALATED ALERT
红灯持续超过5个交易日,系统应触发"小微盘流动性预警",建议减少小盘暴露。
3.4

警戒灯四 · 散户情绪

retail_emotion_light()
MEDIUM
合成公式
散户情绪 = 0.4 × 两融余额z + 0.3 × 新增开户z + 0.3 × 搜索指数z
⚠ INVERSE LOGIC
散户情绪通常作为反向指标。极致高位 → 顶部风险;极致低位 → 底部机会。
反向判定规则
绿灯
综合Z 在 [−1, +1] (中性正常)
黄灯
综合Z 在 [−2, −1] 或 [+1, +2] (情绪偏离)
红灯
综合Z > +2 或 < −2 (极端情绪 → 反向风险)
3.5

警戒灯五 · 北向背离

northbound_divergence_light()
MEDIUM
判定逻辑
计算配置盘和交易盘过去5日累计净流入,根据方向一致性判定。
绿灯
配置盘和交易盘同方向(都正或都负)
黄灯
一方接近0,另一方明显
红灯
明显背离(方向相反且各自|金额| > 20亿)
红灯的二级提示
类型 配置盘 / 交易盘 含义与建议
类型A + / − 长线进场,短线避险 → 潜在底部,可适度布局核心资产
类型B − / + 长线撤退,短线博弈反弹 → 潜在顶部,警惕,准备防御
3.6

警戒灯六 · 政策密度

policy_density_light()

五周落地实施路径

5-Week Implementation Roadmap

从零开始实现状态屏的完整路径。不要试图一次性全部实现。从最关键的5个指标开始,跑顺了再加其他的。

WEEK 1
搭建数据底座
配置PostgreSQL,用akshare拉取过去3年的核心数据,验证数据完整性。
  • PostgreSQL环境配置
  • akshare拉取3年全A成交额、北向、两融、涨停统计
  • 数据完整性校验
  • 建立数据质量监控基础框架
WEEK 2
实现温度计
实现九类资金的Z-score计算,用过去3年数据回测确认阈值合理性。
  • 实现九类资金净流入计算
  • Z-score标准化框架
  • 用3年历史数据回测,确认阈值
  • Streamlit初版温度计可视化
WEEK 3
实现警戒灯
实现六大警戒灯的判定规则,设置告警推送机制。
  • 六大警戒灯规则编码
  • 告警推送配置(企业微信/Telegram/邮件)
  • 历史关键事件回测验证
  • 红灯触发的二级提示开发
WEEK 4
实现状态判定
实现A/B/C/D状态的加权得分计算,人工标注校准阈值。
  • 四种状态得分函数实现
  • 状态分类器与置信度判定
  • 人工标注3年关键时期"正确状态"
  • 调整权重至回测准确率 > 75%
WEEK 5+
迭代优化(持续)
根据实际使用反馈调整阈值,持续校准权重,扩展新数据源和指标。
  • 实战反馈驱动的阈值调整
  • 每季度权重重新校准
  • 新数据源接入
  • 新指标研究和加入
⚠ FINAL REMINDER
记住第一册讲过的原则:70%准确率+持续运行,远胜于100%准确率+永远没上线。先让系统跑起来,再追求完美。
