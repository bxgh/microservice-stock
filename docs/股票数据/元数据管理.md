
# 元数据管理 (issue_price, 申万行业)

本文档描述了系统对核心元数据（发行价、申万行业分类）的管理与同步机制。

## 1. 核心字段：发行价 (Issue Price)

为了满足计算历史最高/发行价倍数及估值空间的需求，我们在 `stock_basic_info` 表中新增了 `issue_price` 字段。

### 数据来源
*   **方法**: 直接抓取同花顺 (10jqka) 公司概况页 HTML。
*   **解析逻辑**: 访问 `http://basic.10jqka.com.cn/{code}/company.html`，提取“发行价格”字段。
*   **优势**: 替代了不稳定的 AkShare `stock_ipo_info` 接口，解决了“No tables found”报错。

### 数据库变更
在 `stock_basic_info` 表中增加：
```sql
ALTER TABLE stock_basic_info ADD COLUMN issue_price DECIMAL(10, 2) DEFAULT NULL COMMENT '发行价格';
```

### 同步机制
*   **服务**: `akshare-api` -> `MetadataService.sync_issue_prices()`
*   **逻辑**: 扫描 `stock_basic_info` 中 `issue_price` 为 NULL 的记录，使用线程池并发抓取并回填。
*   **调度**: 每周六 02:00 自动执行补全（也包含在每周元数据同步任务中）。
*   **手动触发**:
    ```bash
    POST /api/v1/metadata/sync/issue-prices
    ```

## 2. 全量股票列表 (Stock List)

确保数据库中的股票基础信息与全市场同步。

### 数据来源
*   **API**: AkShare `stock_info_a_code_name()` 或 `stock_zh_a_spot_em()`。

### 同步机制
*   **服务**: `akshare-api` -> `MetadataService.sync_stock_list()`
*   **逻辑**: 
    1. 获取全市场 A 股代码与名称。
    2. 统一转换为标准 `600000.SH` 格式。
    3. `ON DUPLICATE KEY UPDATE` 更新名称、市场和上市状态。
*   **手动触发**:
    ```bash
    POST /api/v1/metadata/sync/stock-list
    ```

## 3. 细粒度行业：申万二/三级行业

为了提供比 `stock_basic_info` 更细分的行业分类，系统新增了 `stock_industry_sw` 表，存储申万一级、二级、三级行业分类。

### 数据来源
*   **API**:
    *   L1: `ak.sw_index_first_info()`
    *   L2: `ak.sw_index_second_info()`
    *   L3: `ak.sw_index_third_info()`
    *   Constituents: `ak.sw_index_third_cons(symbol=l3_code)`

### 数据库设计
**Table: `stock_industry_sw`**

| Column | Type | Comment |
| :--- | :--- | :--- |
| `code` | VARCHAR(20) | 标准股票代码 (PK) |
| `l1_code` | VARCHAR(20) | 一级行业代码 |
| `l1_name` | VARCHAR(50) | 一级行业名称 |
| `l2_code` | VARCHAR(20) | 二级行业代码 |
| `l2_name` | VARCHAR(50) | 二级行业名称 |
| `l3_code` | VARCHAR(20) | 三级行业代码 |
| `l3_name` | VARCHAR(50) | 三级行业名称 |
| `update_time` | DATETIME | 更新时间 |

### 同步机制
*   **服务**: `akshare-api` -> `MetadataService.sync_shenwan_industries()`
*   **逻辑**:
    1.  获取所有 L1/L2/L3 行业元数据并构建层级关系树。
    2.  遍历所有 L3 行业，并发获取其成分股列表。
    3.  反向构建 Stock -> Industry 映射。
    4.  批量 Upsert 到数据库。
*   **调度**: 每周六 02:00 自动执行。
*   **手动触发**:
    ```bash
    POST /api/v1/metadata/sync/sw-industries
    ```

## 3. API 接口

### 3.1 触发基础列表同步
*   **URL**: `/api/v1/metadata/sync/stock-list`
*   **Method**: `POST`
*   **Description**: 触发后台任务，全量刷新 `stock_basic_info` 列表。

### 3.2 触发发行价同步
*   **URL**: `/api/v1/metadata/sync/issue-prices`
*   **Method**: `POST`
*   **Description**: 触发后台任务，为缺失发行价的股票进行补全。

### 3.3 触发申万行业同步
*   **URL**: `/api/v1/metadata/sync/sw-industries`
*   **Method**: `POST`
*   **Description**: 触发后台任务，全量刷新申万行业分类数据。

### 3.4 触发同花顺行业同步
*   **URL**: `/api/v1/metadata/sync/ths-industries`
*   **Method**: `POST`
*   **Description**: 触发后台任务，通过问财接口爬取同花顺行业分类及其成分股。此维度作为首选。

### 3.5 触发东方财富行业同步
*   **URL**: `/api/v1/metadata/sync/em-industries`
*   **Method**: `POST`
*   **Description**: **(备选)** 触发后台任务，爬取东方财富行业分类及其成分股。作为同花顺接口不可用时的替代方案。

## 4. 行业数据体系

系统目前维护两套行业分类数据，以满足不同维度的分析需求。

### 4.1 同花顺行业与板块 (THS Sectors) - 首选
*   **来源**: 同花顺问财 (`pywencai-api`)
*   **表结构**: `stock_industry_ths` (行业分级), `stock_sector_ths` (板块字典), `stock_sector_cons_ths` (成分映射)
*   **同步逻辑**: 
    1. **发现阶段**: 通过查询 `所有股票;所属同花顺行业;所属概念` 自动解析全量行业等级与概念列表。
    2. **遍历深挖**: 逐个行业/概念发起成分股查询（如 `{板块名}行业成分股`），确保数据完整性。
*   **同步模式**: 
    *   `standard` (默认): 传统的全量两阶段深挖，耗时较长但数据最全。
    *   `fast`: 单次组合查询（旧逻辑），适合快速刷新。
*   **更新频率**: 建议每周同步一次。
*   **特点**: 指标维度多，行业划分粒度细，市场主流分析基准。
*   **硬件要求**: 由于 `pywencai` 内部运行环境较重，容器内存限制已调至 **512MB**。

### 4.2 东方财富行业 (EastMoney Industries) - 备选
*   **来源**: 东方财富 (`akshare`)
*   **表结构**: `stock_industry_em`
*   **特点**: 接口稳定，作为同花顺数据的补充与兜底。

### 同步机制
*   **服务**: `akshare-api` -> `MetadataService.sync_em_industries()`
*   **Manual Trigger**: `POST /api/v1/metadata/sync/em-industries`
