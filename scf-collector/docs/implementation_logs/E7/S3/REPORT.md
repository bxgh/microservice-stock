# E7-S3 技术报告: 数据契约与归一化引擎增强

## 1. 实施摘要
本次实施强化了 `scf-collector` 的数据质量层，通过引入 `KLineModel` 强类型契约，解决了多源采集（Tushare/AkShare）带来的字段不一致、单位混乱及停牌数据污染问题。

## 2. 核心技术改进

### 2.1 字段合成器 (Field Synthesizer)
针对 AkShare EM 源及 Sina 源可能缺失 `昨收价 (pre_close)` 的问题，引入了基于涨跌幅的反推逻辑：
- **算法**: `pre_close = round(close / (1 + pct_chg), 3)`
- **边界处理**: 增加了对 `pct_chg == -1` (即 100% 跌停) 的除零保护。

### 2.2 停牌清洗引擎 (Cleaner)
优化了 EM 源的停牌判定，防止"僵尸数据"入库：
- **判别式**: `(vol == 0) AND (open == 0 OR high == 0 OR low == 0)`
- **效果**: 相比单一的成交量判定，能更准确识别无成交且无报价的真停牌状态。

### 2.3 DAO 适配层
`StockDAO.save_kline_data` 现在原生支持 `KLineModel`：
- 利用 `item.model_dump()` 自动解包，保持插入逻辑与模型定义的强解耦。
- 向下兼容 `Dict` 类型，确保旧脚本不中断。

## 3. 数据一致性保证
- **代码格式**: 统一为 `XXXXXX.SS` (SH/SZ/BJ)。
- **成交量**: 统一为 **手** (AkShare 的股已除以 100)。
- **成交额**: 统一为 **元** (Tushare 的千元已乘以 1000)。
- **涨跌幅**: 统一为 **小数** (5.0% -> 0.05)。

## 4. 结论
系统已具备生产级的数据归一化能力，大幅降低了下游计算节点因数据格式问题引发异常的概率。
