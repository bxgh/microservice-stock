# Technical Report - E400-S1: P0 核心行情同步

## 1. 技术决策
- **量纲对齐**: 严格遵循 `TABLES_INDEX.md` 规范，所有 `amount` 统一转换为“元”，`pct_chg` 统一转换为“小数”。
- **性能优化**: 对于全 A 5000+ 股票的 K 线写入，虽然当前使用循环 `execute_query`，但预留了批量优化的接口设计。在 SCF 环境下，单日增量写入压力在可控范围内（约 15 分钟）。
- **维表拉链逻辑**: `dim_sw_industry_member` 采用拉链表设计，支持 `in_date` 和 `out_date` 追踪成分股变动，为后续行业归因分析提供基础。

## 2. 数据质量控制 (QC)
- **幂等性**: 所有写入操作均使用 `ON DUPLICATE KEY UPDATE`，确保重复触发时数据不重不漏。
- **空值检查**: 采集器层对 `pct_chg` 和 `amount` 的缺失值进行了 0 值填充，确保 Fact 字段非空。

## 3. 风险评估
- **Tushare 积分限制**: 全 A 批量拉取 `daily` 接口每分钟限制次数较多，需确保 Token 积分 > 2000 以支持高频并发或单次拉取全量。
- **内存占用**: 5000 条 K 线数据转化为 Python 对象后约占用 5-10MB 内存，远低于 256MB 红线。
