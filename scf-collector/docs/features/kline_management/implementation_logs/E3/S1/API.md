# Epic 3 - Story 1 接口与变更说明

本 Story 主要涉及内部云端数据流与数据库架构变更，无公开的 HTTP REST API 变更。相关的微服务内部逻辑调用与数据库字段变动说明如下。

---

## 1. 数据库表架构变更

### 表名: `stock_kline_daily`

在日K线表中新激活了原先预留的 `adj_factor` 字段（双写和单写均支持）：

| 字段名 | 类型 | 说明 | 约束 |
|---|---|---|---|
| `adj_factor` | `decimal(16,4)` | 当日的复权因子，用于下游极速复权计算 | 允许 NULL (但在本 Story 实施后，采集端三防线会确保其 100% 存在，实际不为 NULL) |

---

## 2. 云函数内部接口与 Payload 变更

### 1) 云函数内部操作: `sync_kline_daily`
- **触发机制**: 每日 `16:30` 定时触发，或者通过 API 传入指定日期手动重跑。
- **输入 Payload**:
  ```json
  {
    "op": "sync_kline_daily",
    "trade_date": "2026-05-15"
  }
  ```
- **核心逻辑变更**:
  - 输入的日线行情数据在入库前会在内存中与当日因子合并。
  - 合并因子的优先通道为：本地高效字典映射。
  - 若早晨因子任务未完成，自动降级为 Tushare 实时补货，并触发第二层静默自愈。

### 2) 云函数盘后对账操作: `validate_and_failover`
- **触发机制**: 每日 `17:00` 定时触发。
- **输入 Payload**:
  ```json
  {
    "op": "validate_and_failover",
    "trade_date": "2026-05-15"
  }
  ```
- **核心逻辑变更**:
  - 在执行影子审计和信号就绪发布前，自动执行 `StockDAO.repair_null_factors(trade_date)`。
  - 该操作为第三层防线，若扫描到任一股票的 `adj_factor` 为空，则热修补提取其最新历史因子进行修复。
