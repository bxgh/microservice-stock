⚠️ 央行官网 WAF 屏蔽避坑与国务院政策库动态映射决策 排障避坑

一、 踩坑记录 (The Pitfall)

WAF 网络封锁红线：
在尝试直接向中国人民银行官网（pbc.gov.cn）发起数据采集请求时，网络请求被其部署的网宿安全系统防火墙（WAF）拦截，返回 403 Forbidden 或触发 412 动态 JS 验证挑战。同时人行搜索接口中逆向生成的 RSA 签名头（如 athenaAppKey）具有短期时效性，极易失效。

二、 方案对比 (Options Explored)

方案 优势 劣势与潜在隐患 决策判定
方案 A：云函数 Headless 浏览器 能够完美破解 JS 动态 Cookie 挑战 极度消耗计算资源，在 SCF 中极易超时，公共出口 IP 易被判定为爬虫并遭到永久性拉黑。 ❌ 排除
方案 B：逆向 RSA 搜索签名 执行效率高，网络吞吐开销极低 人行前端混淆加密机制更新频繁，一旦更新数据抓取将瞬间崩塌，人工维护极其繁琐。 ❌ 排除
方案 C：国务院政策库中转动态映射 100% 极其稳定，中国政府网对数据采集高度友好，无需破解任何验证。 需要编写 DOM 表格提取代码进行二次匹配分流。 🟢 优选决策

三、 择优决策 (Optimal Choice)

最终我们采用了 方案 C：中国政府网作为各部委政策的权威中转平台，具有无可比拟的稳定性与高抗载力。我们通过中国政府网的 ZUIXINZHENGCE.json 批量流式抓取后，在详情页内解析政策元数据表格的 发文机关。如果匹配包含 "中国人民银行"，则将 ts_code 映射为 PBC，完美解决了避坑问题。

四、 复用技巧与最佳实践 (Reusable Tips)

# 基于相邻节点定位的高容错解析算法
ts_code = "GOV_CN"
cells = soup.find_all(["td", "th"])
for idx, cell in enumerate(cells):
    text = cell.get_text(strip=True)
    if "发文机关" in text:
        if idx + 1 < len(cells):
            val = cells[idx + 1].get_text(strip=True)
            if "人民银行" in val or "pboc" in val.lower():
                ts_code = "PBC"
            elif "证监会" in val or "证券监督" in val:
                ts_code = "CSRC"
            break
