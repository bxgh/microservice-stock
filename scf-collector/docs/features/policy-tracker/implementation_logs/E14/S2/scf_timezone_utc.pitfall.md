> **核心影响面**：数据对账时效性、宏观政策发布日期、邮件通知渲染时间

## 1. 踩坑记录 (The Pitfall)

### 1.1 异常现象
在 Epic E14-S2 版本的政策分析系统在云端（腾讯云 SCF）运行时，出现了两个隐蔽且严重的**时间戳不对齐**问题：
1. **邮件通知渲染时差**：系统发送的任务报告中，“发生时间”字段显示为 `2026-05-17 12:30:20`，而真实的北京时间其实是 `2026-05-17 20:30:20`。时差整整相差 **8 小时**。
2. **政策发布日期数据污染**：政策采集器在拉取中国政府网（Gov.cn）与证监会（CSRC）的政策时，若网站未标注发布时间，系统会使用当前日期作为兜底。在云端运行时，如果某宏观政策发布在**北京时间 00:00 - 08:00 之间**，云函数记录的 `publish_date` 仍会是**前一天的日期**。这直接破坏了宏观时效分析的时间轴序列。

### 1.2 根源剖析
在 Python 代码中，开发人员使用了以下看似正常的获取当前时间的代码：
```python
# notifier.py
datetime.datetime.now().strftime('%Y-%m-%d %H:%M:%S')

# gov_collector.py / csrc_collector.py
datetime.now().strftime("%Y-%m-%d")
```
当此代码在本地 Windows 操作系统（系统默认时区为东八区 `Asia/Shanghai`）运行时，返回的是标准的北京时间。
然而，一旦代码被打包成 `.zip` 上传到**腾讯云 SCF 容器环境**，由于 Serverless 容器在无状态冷启动时，其底座操作系统的系统时区默认被锁定在 **UTC（协调世界时）**，使得没有显式声明时区参数（naive）的 `datetime.now()` 默认以 UTC 时区进行计算，从而使返回的时间比北京时间晚了整整 8 个小时。

## 2. 方案对比 (Options Explored)

为了让云端环境强制回归东八区时间，我们评估了三种改造方案：

| 维度 | 方案 A：系统环境变量注入 | 方案 B：引入 `pytz` 库 | 方案 C：使用原生 `zoneinfo` (最佳实践) |
| :--- | :--- | :--- | :--- |
| **具体实现** | 在 SCF 控制台为云函数配置 `TZ=Asia/Shanghai` 环境变量。 | `import pytz`<br>`datetime.now(pytz.timezone('Asia/Shanghai'))` | `from zoneinfo import ZoneInfo`<br>`datetime.now(ZoneInfo('Asia/Shanghai'))` |
| **外部依赖** | 依赖腾讯云控制台的物理配置，可维护性较差。 | 强依赖第三方 `pytz` 库，必须将其打包进 Layer 依赖层。 | **无任何三方依赖**，直接使用标准库内置模块。 |
| **可移植性** | 差。换一个云厂商（如阿里云 FC）或本地打包就需要重新配置底层。 | 较好，但增大了 zip 部署包的体积。 | **极佳**。只要运行环境为 Python 3.9+ 即可完美跨平台无缝兼容。 |
| **代码侵入** | 无。但容易在本地 Docker 运行中因为漏设 `TZ` 而重现 Bug。 | 中等。需要修改所有 `datetime.now()` 的调用。 | 中等。只需显式引入 `ZoneInfo`。 |
| **执行开销** | 极小。 | 较大（`pytz` 在大型循环中解析时区会有微弱开销）。 | **极小（C 语言底层实现，性能极高）**。 |

## 3. 择优决策 (Optimal Choice)

由于我们项目的运行环境是 **Python 3.10+** (云端) 以及 **Python 3.11+** (本地)，Python 自 3.9 版本起已经在标准库中内置了高度标准的 **`zoneinfo`** 模块。

为了追求代码的**极致轻量、零外部依赖、高可移植性与金融级高精度**，我们一致决定选择 **方案 C (使用原生 `zoneinfo`)** 作为团队唯一的时区标准解决方案。

## 4. 复用技巧 (Reusable Tips)

在未来的微服务及任何云函数开发中，必须将以下几条红线注入团队的开发习惯中：

### 4.1 强锁时区黄金法则
在任何需要记录时间、入库、输出报告的地方，**绝对禁止**调用无时区的 `datetime.now()`。必须强制锁死 `Asia/Shanghai`：
```python
from datetime import datetime
from zoneinfo import ZoneInfo

# 推荐的最佳实践写法：
cst_now = datetime.now(ZoneInfo("Asia/Shanghai"))
```
