# E12: Tushare 原生数据质量巡检与自动修复体系

## 背景

当前 `stock_kline_daily` 已完成 Tushare 全量重采。为了确保这 2000 万+ 条记录的长期可靠性，系统需要从“一次性迁移校验”转向“常态化质量巡检”。本 Epic 旨在通过理论基准对账、影子源交叉核验及物理逻辑审计，构建 A 股数据质量的最后一道防线。

## 核心规则：三级校验矩阵

### 1. 完备性审计 (Integrity: The "Swiss Cheese" Check)
*   **理论真值计算**：`Theory_Count = COUNT(trade_cal WHERE is_open=1) × COUNT(stock_basic WHERE list_date <= day AND (delist_date IS NULL OR delist_date >= day))`。
*   **审计目标**：发现数据空洞（Holes）。即使 Tushare 返回空，也要通过 AkShare 确认是否为真实停牌。

### 2. 影子源交叉核验 (Shadow: The "Mirror" Check)
*   **影子源选择**：使用 **AkShare (东方财富/新浪口径)** 作为独立审计源。
*   **对齐规则**：抽取 1% 历史样本及 100% 每日新增数据。强制使用“不复权”价格比对。
*   **容错阈值**：价格差异 > 0.01 元或成交量差异 > 1% 触发 `Data_Discrepancy` 告警。

### 3. 物理逻辑审计 (Physics: The "Common Sense" Check)
*   **包含关系**：`high >= open`, `high >= close`, `low <= open`, `low <= close`。
*   **极值检查**：`pct_chg` 异常跳变（如无除权情况下日内变动 > 21%）。
*   **成交量约束**：有成交额必有成交量，涨跌停日成交量通常具有特征分布。

## 风险与避坑提示

| 风险 | 表现 | 应对 |
|---|---|---|
| **AkShare 限流** | 影子校验触发过于频繁导致 IP 被封 | 实施随机抽样算法，非连续性扫描 |
| **四舍五入漂移** | 不同源之间 0.01 元的精度差异导致误报 | 比对逻辑加入 `abs(diff) < 0.011` 的容差 |
| **假性空洞** | 早期 A 股（90年代）数据本身极其稀疏 | 建立“历史低质量区”白名单，降低 1995 年前的告警权重 |

## Story 设计

### E12-S1: [L2] 基于理论日历的全量完整性对账 (Gap Detector)

**作为** Data Quality Steward，**我希望** 通过交易日历与上市清单的比对，**以便** 发现并补齐 Tushare 采集过程中的任何遗漏。

#### 任务
- E12-S1-T1 编写 `check_kline_holes.py`，计算每日应有股票数量 vs 实际记录数
- E12-S1-T2 输出空洞分布清单至 `meta_task_queue`
- E12-S1-T3 建立停牌状态缓存表，过滤假性空洞

#### 验收标准 (AC)
- **AC1**: 脚本必须能准确识别出如“某日全市场缺失 5 只个股记录”的情况，并剔除当天未上市或已退市的个股。

---

### E12-S2: [L3] 影子源价格对账与逻辑审计 (Accuracy Shadowing)

**作为** DB Auditor，**我希望** 将本地数据与 AkShare 进行像素级对齐，**以便** 识别并纠正 Tushare 的原始数据错误。

#### 任务
- E12-S2-T1 实现 `shadow_validator.py`，支持多进程异步调用 AkShare 抓取对比样本
- E12-S2-T2 建立物理逻辑过滤器（`high < low` 等极端错误捕捉）
- E12-S2-T3 在 `REPORT.html` 中可视化展示数据准确率趋势

#### 验收标准 (AC)
- **AC1**: 抽样比对必须涵盖 OHLC、Volume、Amount 四个核心维度。

---

### E12-S3: [E6] 任务化自愈流水线 (Self-Healing Pipe)

**作为** Cloud Collector，**我希望** 系统发现错误后能自动重采，**以便** 无需人工干预即可维持高纯净度数据库。

#### 任务
- E12-S3-T1 完善 `auto_repair_worker`，支持根据 Task ID 进行强制覆盖重采
- E12-S3-T2 建立修复前后的快照存证机制
